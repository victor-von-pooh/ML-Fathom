# 設計

ML-Fathom の設計の方針をまとめる.

## 目的

機械学習に使うデータを, 画面の上で読み込み, 探索的に分析し (EDA), 前処理をして, 学習 (ML-Found) にそのまま渡せる形に書き出すローカルの Web アプリ.
コードを書かずに, データの形と特徴をつかみ, 学習の前に確かめた方がよいこと (気付き) を見て, 前処理の手順を組み立てる.

- 読み込み, 分析, 気付き, 前処理, 書き出しは全て ML-EDA が行う. このアプリは画面と, 登録したデータとレシピの置き場だけを受け持つ
- ML-EDA は submodule にする (ML-Dashboard と ML-Found, ML-CreateArchitecture と ML-ModelControl の関係と同じ)

## 全体の中での役割

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「データの分析」の段階で画面を受け持つ. ライブラリは ML-EDA.

- 書き出すデータセットの形 (`dataset.yaml`) は ML-EDA が持つ約束. 学習のスクリプトは ML-EDA の `load_dataset` で読む
- 目的の列とタスクの種類は, 今は画面で選ぶ. 問題の設定の段階ができたら, そこから受け取る
- 将来は他の段階の画面と 1 つのアプリにまとめる. そのため構成と道具を ML-Dashboard と ML-CreateArchitecture にそろえる

## 構成

| 部分 | 中身 |
| --- | --- |
| バックエンド | Python, FastAPI. ML-EDA を呼ぶ API, 登録したデータの一覧, データごとのレシピ, 書き出したデータセットの置き場 |
| 画面 | TypeScript, React, Vite, React Router. グラフは ECharts (ML-Dashboard と同じ) |

## 置き場

`~/.ml-fathom/` (環境変数 `ML_FATHOM_HOME` で変えられる) に置く. 元のデータのファイルは読むだけで, 書き換えない.

| 場所 | 中身 |
| --- | --- |
| `sources.json` | 登録したデータ (ID, 名前, 場所, 読み込み, 読み込みの設定, 種類, 目的の列) |
| `recipes/<ID>.yaml` | データごとの前処理のレシピ |
| `datasets/<名前>/` | 書き出した学習用のデータセット (ML-EDA の `export_dataset`) |

読み込んだデータと分析の結果は, ファイルの更新時刻と設定ごとにメモリに覚える (ファイルが変われば読み直す).

## 画面

1. **データ**: 登録したデータの一覧. 「見本のデータを入れる」で, 操作を試すための見本 (顧客の解約の表, 電力の使用量の時系列, 図形の画像, レビューの文, 物体の点群. どれも学習の前に直すことを含む) を置き場の `samples` に作って登録する. 「データを追加」で, ディレクトリをたどってファイルかディレクトリを選び, ML-EDA が判定した読み込みの候補 (確からしさの順) から選んで登録する
2. **データごとの画面**: 上で目的の列を選ぶ (分析に目的の列との関係が加わる). 表の読み込み (csv, json, parquet, excel) は「読み方」で, 自動, 表 (日時の列があっても時系列にしない), 時系列 (時刻の列), 文 (文の列. 語の番号の並びにして学習する) を選べる (ML-EDA の読み込みの kind, time_column, text_column). タブで切り替える
    - **概要と気付き**: 種類, 行, 列, 欠損, 重複, メモリと, 気付きの一覧 (列の名前を押すとその列の詳細へ)
    - **列**: 列の一覧 (型と気付きの印) と, 選んだ列の統計とグラフ (数値はヒストグラム, カテゴリは頻度, 文は長さと頻出語)
    - **関係**: 目的の列の分布と, 各列との関連の強さ. 数値の列の相関 (Spearman と Pearson) と, カテゴリの列の関連 (Cramér の V) のヒートマップ
    - **時系列** (時系列だけ): 時刻の間隔, 抜け, 期間, 系列のグラフ (範囲を変えられる), 自己相関と周期の候補
    - **中身を見る** (画像, 文, 点群): 件数, 大きさや点の数の分布, 読めないファイルの数と, 1 件ずつの中身 (画像は並べて, 文は一覧, 点群は回せる 3D 表示). ラベルやファイルの名前で絞り込める
    - **表の中身**: 並べ替え, 絞り込み, ページ送り
    - **前処理と書き出し**: 下
3. **データセット**: 書き出したデータセットの一覧

## 前処理の組み立て

- 左に目的とタスクと分割, 手順の並び (足す, 消す, 並べ替え, 引数を変える), 保存と書き出し. 右に手順をかけた前と後の表
- 手順の番号を押すと, その手順の前と後を並べる (足した列と消えた列に色). 押していないときは全ての手順の後と, 学習用のデータ (分割ごとの行数, 学習に使う列の数, クラス, 学習の前に直すことの注意)
- **気付きから手順を足す**: 気付きに合う手順を足す (ID らしい列と定数の列を落とす, 欠損の多い列を埋める (数値は中央値, それ以外は最も多い値), 偏った分布の対数, 外れ値の切り詰め, 表記のゆれをそろえる (目的の列も), 同じ文を落とす, 空の文を除くなど). 画像, 文, 点群でも使える
- **学習できる形にする手順を作る**: 列の型から, 全ての列を数値にし欠損を無くす手順を作る (文, ID, 定数の列を落とす, 日時を分解, カテゴリをワンホットか番号付け, 欠損を埋める, 偏った数値の対数. 重複した行を落とし, 表記のゆれをそろえる. 時系列は, 数値の列 (目的の列も) の 1 つ前と, 自己相関で見つけた 1 周期前の値, 1 周期の移動平均の列を足し (店ごとのような複数の系列は, 系列を分ける列を符号化する前に `by` で系列ごとに), 過去が足りない始めの行を落とし, 時刻の列から曜日と月 (1 日より細かい間隔なら時と曜日) の列を足す. 最後に標準化)
- タスクを決めていないレシピは, 目的の列から推定したタスク (分類か回帰) で始める
- **中身の手順** (画像, 文, 点群): 表の手順の後に, 1 件ずつの中身を同じ形の配列にする手順 (item_steps) を並べる. 「学習用の配列にする手順を作る」で分析の結果から作る (画像は最も多い大きさに resize, 色の形式が混ざれば rgb, normalize. 文は語数の第 3 四分位の 1.5 倍の長さの vocabulary. 点群は点の数の中央値 (1024 まで) の sample_points と normalize_cloud). 読めない件があれば, 表の手順の先頭に filter_rows (画像は width が notna, 点群などは error が isna) も足す. 画像などは, 中身を読まずに (`prepare(..., read_items=False)`) 中身の手順を確かめ, 読めない件や大きさ, 色の形式, 点の数のばらつきの注意と分割の件数とクラスを出す (全ての中身は書き出しのときに読む). 写真のような大きな画像は長い辺を 224 までに縮め, 空白で区切らない文は文字ごとの語彙にする
- **中身の手順の前と後** (画像, 文, 点群): 「数件で試す」で, 学習用の少ない見本 (100 件) で当てはめた中身の手順を, 学習用から選んだ 8 件にかけた前と後を出す (`POST /api/sources/{id}/item_preview`. ML-EDA の `preview_items`). 画像は並べ, 文は語に戻した番号の並び, 点群は 2 つの 3D 表示
- 画像, 文, 点群のディレクトリは, クラスのフォルダの名前の label を目的の列にして登録する
- 書き出すと, ML-Found の学習スクリプトで読み込む例を出す

## API

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/info` | 読み込み, 前処理の手順, 中身の手順の一覧 |
| `GET /api/browse?path=` | ディレクトリの中身 (隠しファイルを除く) |
| `POST /api/detect` | 場所を読める読み込みの候補 |
| `POST /api/samples` | 見本のデータを作って登録 (登録済みの場所は飛ばす) |
| `GET, POST /api/sources` | 登録したデータの一覧と登録 (読めることを確かめる) |
| `PATCH, DELETE /api/sources/{id}` | 名前, 目的の列, 読み込みの設定の変更と, 登録を外す |
| `GET /api/sources/{id}/profile` | 分析の結果 |
| `GET /api/sources/{id}/rows` | 表の中身 (並べ替え, 絞り込み, ページ) |
| `GET /api/sources/{id}/items/{index}?size=` | 1 件の中身 (画像は PNG で, size で縮める. 点群は有限の点の JSON (5 万点まで間引く)) |
| `GET, PUT /api/sources/{id}/recipe` | レシピ |
| `POST /api/sources/{id}/preview` | 手順をかけた前と後 (画像などは分割の件数とクラス) |
| `POST /api/sources/{id}/item_preview` | 中身の手順を数件にかけた前と後 |
| `POST /api/sources/{id}/export` | 学習用に書き出す |
| `GET /api/datasets` | 書き出したデータセットの一覧 |

## 安全

ML-CreateArchitecture と同じ. 127.0.0.1 で待ち受け, 起動ごとのトークンを求め, 他のサイトからの書き込みと別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

## 段階

| 段階 | 内容 |
| --- | --- |
| 1 | 表と時系列の分析, 前処理, 書き出し |
| 2 | 画像, 文, 点群の中身の表示, 分析, 中身の手順と書き出し |
| 3 | 問題の設定の段階との連携 (目的とタスクを受け取る) |
