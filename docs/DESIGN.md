# 設計

ML-Fathom の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

機械学習に使うデータを, 画面の上で読み込み, 探索的に分析し (EDA), 前処理をして, 学習 (ML-Found) にそのまま渡せる形に書き出すローカルの Web アプリ. 「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作る) のうち, 「データの分析」の段階の画面.
コードを書かずに, データの形と特徴をつかみ, 学習の前に確かめた方がよいこと (気付き) を見て, 前処理の手順を組み立てる.

- 将来は他の段階の画面と 1 つのアプリにまとめる. そのため構成と道具を ML-Dashboard と ML-CreateArchitecture にそろえる

| 部分 | 中身 |
| --- | --- |
| バックエンド | Python, FastAPI. ML-EDA を呼ぶ API, 登録したデータの一覧, データごとのレシピ, 書き出したデータセットの置き場 |
| 画面 | TypeScript, React, Vite, React Router. グラフは ECharts (ML-Dashboard と同じ) |

## 2. 使うライブラリと約束

ライブラリは ML-EDA (submodule. ML-Dashboard と ML-Found, ML-CreateArchitecture と ML-ModelControl の関係と同じ). 問題の設定を読み書きするために ML-Quest も submodule にする.

- 読み込み, 分析, 気付き, 前処理, 書き出しは全て ML-EDA が行う. このアプリは画面と, 登録したデータとレシピの置き場だけを受け持つ
- 読み書きするファイル:

| ファイル | 読むか書くか | 約束 |
| --- | --- | --- |
| 元のデータ (表, 時系列, 画像, 文, 点群, 多視点の撮影, 音声) | 読むだけ | ML-EDA の読み込み. 書き換えない |
| 記録した軌跡 (`<名前>.csv` か `<名前>.parquet` と, 説明の `<名前>.json`) | 読むだけ | ML-EDA の「記録した軌跡」の約束 (`load_trajectory` で読み, `describe_trajectory` で要約する). 書き換えない (下の「12. 記録した軌跡の分析」) |
| 軌跡の分析 (`<軌跡の名前>.analysis.json`) | 書く (ブラウザで保存) | ML-EDA の `describe_trajectory` の結果のまま (下の「12. 記録した軌跡の分析」) |
| 並べるの反応の表 (問題の設定に入れた, 1 行が 1 つの反応の表のファイル 1 つ) | 読む, プロジェクトに写す | ML-EDA の「並べるの反応の表」の約束 (`load_reactions` で読み, `describe_reactions` で要約する). 元のファイルは書き換えず, 前処理をかけないファイル 1 つのまま `project.dataset` に写す (下の「13. 並べるの反応の表の分析」) |
| 群分けの表 (登録した表と時系列のうち, 正解の無い 1 行が 1 つの対象の表) | 読む, データセットに書く | ML-EDA の「群の要約」と「群分けの表」の約束 (`describe_groups` で学習に通さず群の要約を求め, `export_group_rows` で分析の保存として版 2 のデータセットに書く. 版 2 は学習には使わない). 学習へは表のファイルを渡す. まとめるの問題の設定から始めた表は, 前処理をかけないファイル 1 つのまま `project.dataset` に写す (ML-Quest のまとめるの骨組みは表のファイルを問題の設定の読み方で読むため). 元のファイルは書き換えない (下の「14. 群分けの表の分析」) |
| `dataset.yaml` と書き出したデータセット | 書く, 一覧で読む | ML-EDA の約束. 版 1 (1 件 = 1 行の表. `load_dataset` で読む) と版 2, 版 3 (入力と正解がファイルの組. 版 3 は項目ごとに書き出しでかけた中身の手順 (`steps`) を持つ. どちらも `load_items` で読む. 読む版の組は ML-EDA の `ITEMS_FORMAT_VERSIONS`). 知らない版は「読めない版」と出す (下の「8. データセットの一覧」). 版 1 のモデルに要るものは ML-EDA の `model_inputs` で読む |
| `problem.yaml` (問題の設定) | 読む, 書き戻す | ML-Quest の形. 版 1 と版 2 を読み, 版 2 で書き戻す. ML-Pathfinder の置き場の `problems/<識別子>/problem.yaml` を一覧にする. ML-Quest がプロジェクトを作ったときの記録 (`project.path`, `project.dataset`, `project.model_spec`. 書いていない問題の設定もある) を読み, `project.dataset` を書き出し先にする (`project.model_spec` は一覧で返すだけ) (下の「11. 問題の設定から始める」) |
| レシピ (`recipes/<ID>.yaml`) | 読み書き | ML-EDA のレシピの形 |

- 目的の列とタスクの種類は画面で選ぶか, 問題の設定から受け取る
- アプリのコードは ML-EDA と ML-Quest の公開の名前 (`__all__`) だけを使う (中の作りが変わっても画面が壊れないように). 公開を待つ名前を使う場合は `tests/test_public_names.py` の表 (`WAITING`) に置き, 待っている理由を TODO.md に書く (今は無し). 組のライブラリに別名を付ける import (`import ml_eda as e`) は, 別名の後の名前を確かめられないので使わない. JSON の応答にする変換 (`to_json`) は画面の受け持ちなので, このアプリが持つ. ML-EDA の分析の結果と NaN の扱いがずれないよう, ML-EDA の `profile.to_json` と同じ決まりにする

## 3. 画面

1. **データ**: 登録したデータの一覧. 「見本のデータを入れる」で, 操作を試すための見本 (顧客の解約の表, 電力の使用量の時系列, 図形の画像, レビューの文, 物体の点群. どれも学習の前に直すことを含む) を置き場の `samples` に作って登録する. 「データを追加」で, ディレクトリをたどってファイルかディレクトリを選び, ML-EDA が判定した読み込みの候補 (確からしさの順) から選んで登録する
2. **データごとの画面**: 上で目的の列を選ぶ (分析に目的の列との関係が加わる). 表の読み込み (csv, json, parquet, excel) は「読み方」で, 自動, 表 (日時の列があっても時系列にしない), 時系列 (時刻の列), 文 (文の列. 語の番号の並びにして学習する) を選べる (ML-EDA の読み込みの kind, time_column, text_column). 「読み込みの設定」で, 読み込みのその他の設定 (Excel のシート, 区切り文字, 文字コード, ヘッダーの行など. ML-EDA の読み込みが持つもの) を変えられる. 空の欄は読み込みが推定する. 真偽の設定 (画像の `digest`, 画像, 点群, 撮影, 音声の `follow_links`) は既定, true, false から選ぶ (取り違えた文字を送らないように). 読めない設定は保存しない. 分析に失敗しても直せるように, 分析の結果が無いときも出す タブで切り替える
    - **概要と気付き**: 種類, 行, 列, 欠損, 重複, メモリと, 気付きの一覧 (列の名前を押すとその列の詳細へ)
    - **列**: 列の一覧 (型と気付きの印) と, 選んだ列の統計とグラフ (数値はヒストグラム, カテゴリは頻度, 文は長さと頻出語)
    - **関係**: 目的の列の分布と, 各列との関連の強さ. 数値の列の相関 (Spearman と Pearson) と, カテゴリの列の関連 (Cramér の V) のヒートマップ
    - **時系列** (時系列だけ): 時刻の間隔, 抜け, 期間, 系列のグラフ (範囲を変えられる), 自己相関と周期の候補
    - **中身を見る** (画像, 文, 点群): 件数, 大きさや点の数の分布, 読めないファイルの数と, 1 件ずつの中身 (画像は並べて, 文は一覧, 点群は回せる 3D 表示). ラベルやファイルの名前で絞り込める. 読めない件は, 一覧に表の `error` の理由 (外を指すリンクなど) を出し, 画像はその件の中身を読みに行かない. 点群, 音声, 撮影で選んだ件が読めなければ, 1 件の中身の API の理由を出す
    - **中身を見る** (音声. ML-EDA の `audio`): 件数, 標本化の周波数とチャンネルの数の内訳, 長さ (中央値と範囲), 読めないファイルの数と, 一覧 (ラベル, 周波数, チャンネル, 長さ) から 1 つを選ぶと, その音声の再生 (ブラウザの音の再生の部品) と波形. 再生と波形は先頭の 30 秒だけ (長い録音で大きな音を送らないように. 切った場合はそう添える). 波形はチャンネルを平均した振幅を区間ごとの最小と最大で描く
    - **中身を見る** (多視点の撮影. ML-EDA の `capture`): 撮影の一覧 (枚数, 信頼できる深度の割合, 方位の隙間) から 1 つを選ぶと, 上から見たカメラの配置 (ML-EDA の `capture_layout`. 物の中心と各カメラ, 追跡できなかった枚, 最も大きい隙間の向き), 各枚の画像の小さな一覧 (画像, 深度, 信頼度を切り替える. 深度は欠けを除いた 2 % 点から 98 % 点で明るさにする (遠い数画素で全体が暗くならないように). 信頼度は値のまま), 撮影に点群があれば回せる 3D 表示. 版 1 の前処理と書き出しは ML-EDA が撮影を扱わないので, 前処理のタブはそう知らせ, 撮影と点群の対の書き出し (下の「9. ファイルの組の書き出し」) へ案内する
    - **群分け** (表と時系列だけ): 群を作る列と群の数を選んで, 学習に通さずに作った群の要約を見て, 群分けの表を分析用に書き出す (分析の保存). まとめるの問題の設定から始めた表は, 問題の設定の答えで欄を埋めて開き, 学習のプロジェクトへ表のファイルを書き出せる (下の「14. 群分けの表の分析」)
    - **表の中身**: 並べ替え, 絞り込み, ページ送り. 値は ML-EDA の `frame_view` の形 (前処理の前と後と同じ見え方にするため). 欠損と無限大は「欠損」と出す
    - **前処理と書き出し**: 下
    - 記録した軌跡は, 上のタブの代わりに軌跡の分析のタブを出す (下の「12. 記録した軌跡の分析」)
    - 並べるの問題の設定から始めた反応の表は, 上のタブの代わりに反応の表の分析のタブを出す (下の「13. 並べるの反応の表の分析」)
3. **データセット**: 書き出したデータセットの一覧 (下の「8. データセットの一覧」. 表のデータセットはモデルに要るもの (入力の形と型, 文なら語彙の大きさ, 出す値の数) も出す). 「ファイルの組を書き出す」で, 入力と正解がファイルの組のデータセット (版 2. 中身の手順をかければ版 3) を書き出す画面に移る (下の「9. ファイルの組の書き出し」)

## 4. API

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/info` | 読み込み, 前処理の手順, 中身の手順 (`item_steps`. 引数の上限 `limits` 付き) の一覧と, ファイルの組の書き出しで項目ごとに選べる中身の手順 (`pair_steps`) |
| `GET /api/browse?path=` | ディレクトリの中身 (隠しファイルを除く) |
| `POST /api/detect` | 場所を読める読み込みの候補 (記録した軌跡として読めれば `trajectory` を先頭に) |
| `POST /api/samples` | 見本のデータを作って登録 (登録済みの場所は飛ばす) |
| `GET, POST /api/sources` | 登録したデータの一覧と登録 (読めることを確かめる) |
| `PATCH, DELETE /api/sources/{id}` | 名前, 目的の列, 読み込みの設定の変更と, 登録を外す |
| `GET /api/sources/{id}/profile` | 分析の結果 |
| `GET /api/sources/{id}/trajectory` | 記録した軌跡の要約 (ML-EDA の `describe_trajectory` の結果. 軌跡でないデータは 422) |
| `GET /api/sources/{id}/reactions` | 並べるの問題の設定の列で読んだ反応の表の要約 (ML-EDA の `describe_reactions` の結果と, 問題の設定の名前, 場所, 並べる件数. 並べるの問題の設定から始めていないか, 反応の表として読めなければ 422) |
| `POST /api/sources/{id}/export_reactions` | 反応の表をファイル 1 つのまま, 問題の設定のプロジェクトの書き出し先 (`project.dataset`) に写す (既にあるファイルは `overwrite` を付けた場合だけ置き換える) |
| `POST /api/sources/{id}/groups` | 選んだ列 (`columns`) と群の数 (`k`. 2 から 50), 乱数の種 (`seed`), 安定性の数え方 (`stability`. `seed` か `sample`. 既定 `seed`) で, 学習に通さずに作った群の要約 (ML-EDA の `describe_groups` の結果. 表と時系列でないデータ, 列と群の数の誤りは理由を付けて 422) |
| `POST /api/sources/{id}/export_groups` | 群を作る列と行を見分ける列 (`id`. 任意) を, 群分けの表として置き場の `datasets` の下に, 分析の保存として版 2 で書き出す (ML-EDA の `export_group_rows`. 学習には使わない. 分割は `random` か `none`. 既にある名前は `overwrite` を付けた場合だけ置き換える) |
| `GET /api/sources/{id}/group_problem` | 始めた問題の設定の名前と場所, まとめるの答え (`group`. 群を作る列, 行を見分ける列, 群の数, 安定性の数え方. まとめるで学習する受け持ちでなければ `null`) と, プロジェクトの書き出し先とその様子 (`project`. 無い, ファイル, ファイルでない) |
| `POST /api/sources/{id}/group_problem/check` | 群分けのタブの選び方 (`group`. 群を作る列, 行を見分ける列, 群の数) を, まとめるの問題の設定に試しに書き戻した結果 (変わる点と中身の印. 保存はしない. ML-Quest の `apply_group` が断る選び方は理由を付けて 422) |
| `POST /api/sources/{id}/group_problem/write` | 群分けのタブの選び方を, 確かめたときの中身の印 (`version`) とともに問題の設定の `ml.parts.<n>.group` に書き戻して保存する (確かめた後に問題の設定が変わっていれば 409) |
| `POST /api/sources/{id}/export_group_project` | まとめるの問題の設定から始めた表をファイル 1 つのまま, プロジェクトの書き出し先 (`project.dataset`) に写す (既にあるファイルは `overwrite` を付けた場合だけ置き換える) |
| `GET /api/sources/{id}/rows` | 表の中身 (並べ替え, 絞り込み, ページ) |
| `GET /api/sources/{id}/items/{index}?size=` | 1 件の中身 (読み込んだディレクトリの外を指すリンクの件は, ML-EDA の `load_item` の理由 (設定 `follow_links` の案内) を添えて 422. 外かの判定は ML-EDA に任せ, 読み込みの設定 `follow_links` が true のデータでは外も読む. 画像は PNG で, size で縮める. 点群は有限の点の JSON (5 万点まで間引く). 多視点の撮影は各枚 (番号, 追跡, 画像と深度と信頼度の有無) と上から見たカメラの配置と点群の有無の JSON. 音声は周波数, チャンネル, 全体の長さ, 見せる長さ (先頭の 30 秒まで), 区間ごとの振幅の最小と最大の JSON) |
| `GET /api/sources/{id}/items/{index}/audio` | 音声の先頭の 30 秒までを再生用の WAVE (16 bit の PCM. 3 チャンネル以上は平均して 1 チャンネルに) で返す. 音は ML-EDA の `load_item(index, seconds)` で先頭の秒だけを読む |
| `GET /api/sources/{id}/items/{index}/frames/{frame}?layer=&size=` | 多視点の撮影の 1 枚の PNG (`layer` は image, depth, confidence. 深度は欠けを除いた 2 % 点から 98 % 点で 0 から 255 に, 信頼度は値のまま. 場所は ML-EDA が撮影のディレクトリの中に限ったものだけ) |
| `GET /api/sources/{id}/items/{index}/cloud` | 多視点の撮影の点群の JSON (5 万点まで間引く) |
| `GET, PUT /api/sources/{id}/recipe` | レシピ |
| `POST /api/sources/{id}/preview` | 手順をかけた前と後 (全ての手順なら, 学習に使う列, 分割の件数, クラス, 注意と, 分割の後の気付き `findings`) |
| `POST /api/sources/{id}/item_preview` | 中身の手順を数件にかけた前と後 |
| `POST /api/sources/{id}/export` | 学習用に書き出す (場所, dataset.yaml の中身, モデルを組むときの数) |
| `GET /api/sources/{id}/project` | 始めた問題の設定のプロジェクトの書き出し先と, その場所の今の様子 (無い, データセット, データセットでない. 並べるの反応の表とまとめるの表では, 無い, ファイル, ファイルでない) |
| `POST /api/sources/{id}/export_project` | 問題の設定のプロジェクトの書き出し先 (`project.dataset`) に書き出す (既にあるデータセットは `overwrite` を付けた場合だけ置き換える) |
| `GET /api/datasets` | 書き出したデータセットの一覧 (版 1, 版 2 と版 3, 読めないものを `form` で分ける. 版 1 はモデルに要るもの `model` を持つ. プロジェクトへ書き出したものも並べる) |
| `POST /api/datasets/image_masks` | 画像と領域の対を版 2 (中身の手順を渡せば版 3) で書き出す (場所, dataset.yaml の中身, 注意) |
| `POST /api/datasets/capture_clouds` | 多視点の撮影と点群の対を版 2 (中身の手順を渡せば版 3) で書き出す (場所, dataset.yaml の中身, 注意) |
| `GET /api/problems` | ML-Pathfinder の置き場の問題の設定の一覧 (名前, 場所, 更新時刻, 始められるか, プロジェクトの記録) |
| `POST /api/problems/start` | 問題の設定から, データを登録してレシピと始めたときの知らせを保存する (ファイルの組の受け持ちは登録せず, ファイルの組の書き出しの画面へ移る値を返す. 並べるは反応の表を登録し, まとめるは表を登録して開くタブ (`tab: groups`) を返し, どちらもレシピを保存しない) |
| `GET /api/problems/pairs?path=` | ファイルの組の受け持ちの問題の設定の, 書き出しの設定の下書き, 知らせ, 中身の印, プロジェクトの書き出し先とその様子 |
| `POST /api/problems/pairs/export` | ファイルの組をプロジェクトの書き出し先 (`project.dataset`) に書き出し, 書き出しの設定 (中身の手順 `options.item_steps` も) を問題の設定に書き戻す |
| `POST /api/sources/{id}/problem/check` | 編集中のレシピを問題の設定に試しに書き戻した結果 (変わる点, 食い違い, 選ぶ問い) |
| `POST /api/sources/{id}/problem/write` | 選んだ答えとともに問題の設定に書き戻す |

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| データ | 登録した分析するファイルかディレクトリ. 登録しても元のファイルは変えない |
| 種類 | ML-EDA が判定したデータの形. 表, 時系列, 画像, 文, 点群, 多視点の撮影, 音声. 記録した軌跡 (`trajectory`) は, このアプリが ML-EDA の `load_trajectory` で読めるかで決める. 並べるの反応の表 (`reactions`) は, 並べるの問題の設定から始めたかで決める |
| 反応の表 | 並べる (推薦) の学習に使う, 1 行が 1 つの反応 (利用者が品物を買った, 見たなど) の表. 利用者, 品物, 時刻の列と, 任意の反応の強さの列 (ML-EDA の「並べるの反応の表」) |
| 群の要約 | 群分け (まとめる) で, 群ごとの行の数, 割合, 安定性と, 群を作った列の要約 (数の列は平均, 他の列は最も多い値と割合) を並べた表と, 群全体の安定性 (調整ランド指数) とまとまり (シルエット係数) (ML-EDA の「群の要約」) |
| 群分けの表 | 群分け (まとめる) の, 正解の無い 1 行が 1 つの対象の表. 学習へは表のファイルのまま渡す. 分析の保存として版 2 の受け持ち `group` のデータセットにも書ける (ML-EDA の「群分けの表」) |
| 軌跡 | 強化学習の方策を環境で走らせた記録. 1 歩が 1 行の表と説明 (ML-EDA の「記録した軌跡」) |
| 目的の列 | 予測したい列. 画像などはクラスのフォルダの名前 (`label`) |
| 気付き | 学習の前に確かめた方がよいこと (ML-EDA の `findings`). 注意と参考の 2 段階 |
| レシピ | 前処理の手順の並びと分割 (ML-EDA のレシピの形). データごとに 1 つ |
| 中身の手順 | 画像, 文, 点群, 音声の 1 件ずつを同じ形の配列にする手順 (`item_steps`) |
| データセット | 書き出した学習用のデータ (`dataset.yaml` を持つディレクトリ). 版 1 は 1 件 = 1 行の表, 版 2 と版 3 は入力と正解がファイルの組 (版 3 は中身の手順をかけたもの) |

## 6. 置き場

`~/.ml-fathom/` (環境変数 `ML_FATHOM_HOME` で変えられる) に置く. 元のデータのファイルは読むだけで, 書き換えない.

| 場所 | 中身 |
| --- | --- |
| `sources.json` | 登録したデータ (ID, 名前, 場所, 読み込み, 読み込みの設定, 種類, 目的の列, 始めた問題の設定の場所と始めたときの知らせ, プロジェクトへ書き出した場所) |
| `recipes/<ID>.yaml` | データごとの前処理のレシピ |
| `datasets/<名前>/` | 書き出した学習用のデータセット (ML-EDA の `export_dataset` (版 1) と, `export_image_masks`, `export_capture_clouds` (版 2, 版 3), `export_group_rows` (版 2)) |

読み込んだデータと分析の結果は, ファイルの更新時刻と設定ごとにメモリに覚える (ファイルが変われば読み直す).

問題の設定の一覧は ML-Pathfinder の置き場 (`~/.ml-pathfinder/`. ML-Pathfinder と同じ環境変数 `ML_PATHFINDER_HOME` で変えられる) の `problems/*/problem.yaml` を読む. 2 つのアプリを同じ置き場で使うため, 環境変数も同じものにする.

## 7. 安全

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない. 画像, 点群, 撮影, 音声のディレクトリの中の, 読み込んだディレクトリの外を指すシンボリックリンクは, 既定では一覧, 分析, 1 件の中身, 中身の手順, 版 1 の書き出しのどれでも読まない (ML-EDA の読み込みの決まり. 画面から渡した場所の中のリンクで, 手元の思わぬファイルを見せないため). ファイルの組の書き出し (下の「9. ファイルの組の書き出し」. ML-EDA の `export_image_masks`, `export_capture_clouds`) は, ML-EDA の決まりで今はリンクの先をたどる. 共有の保存先へのリンクで置いたデータは, 読み込みの設定 `follow_links` を true にして読む. データセットの一覧も, 外を指すリンクの `dataset.yaml` は読まない (下の「8. データセットの一覧」). 「プロジェクトへ書き出す」の書き出し先 (`project.dataset`) は, リンクをたどった後もプロジェクトの中のものだけにする (問題の設定のファイルを書き換えて, 外のファイルを置き換えさせないため. 下の「11. 問題の設定から始める」). 書き込みの直前には, 親の実体をプロジェクトと比べ直し, プロジェクトから途中のディレクトリを一段ずつリンクをたどらずに開く (無ければ作る). 確かめの後に別のプロセスが途中の場所をシンボリックリンクかファイルに替えていれば, 理由付きの 422 で断る. 断るか書き出しに失敗すれば, ここで作った途中のディレクトリ (空のもの) を消す (確かめと書き込みの間の差し替えで外に書かせないため). 反応の表と群分けの表の写しと, 版 1 とファイルの組の書き出し (ML-EDA の引数 `parent` に開いた親の記述子を渡す) は, 開いた親のディレクトリに対して書く (書いている最中に途中の場所が替わっても外に書かないため). 版 1 の書き出しは書いた後にモデルの入力の数をパスで読むので, 読む前に書き出し先の親のパスが今も開いた親を通るか (装置と i-node の番号) を比べ, 替わっていれば読まずに理由付きの 422 で断る (データセットは替わる前の場所にある). 写しは書き出し先の名前のリンクをたどらずに比べて置き換え, 書き出し先がリンクなら, リンクの先を書き換えず, リンクの項目を写したファイルで置き換える (様子の確かめで断った後にリンクに替わっても外に書かないため. リンクが登録した表そのものを指していても写す).

## 8. データセットの一覧

置き場の `datasets` の下と, プロジェクトへ書き出した場所 (下の「並べる場所」) の `dataset.yaml` を持つディレクトリを, `format_version` で分けて読む (ML-EDA の `load_dataset` はファイルの組の版で, `load_items` は版 1 で止まるので, 版を見てから読む方を選ぶ). 一覧の 1 件は `form` で形を表す.

- **版 1** (`form: table`): 種類とタスク, 目的の列, 学習に使う列の数, 分割ごとの行数 (`load_dataset`) と, モデルに要るもの (`model`. ML-EDA の `model_inputs` の結果: 入力の名前と形と型, タスク, クラス, 出す値の数). モデルの定義 (ML-ModelControl の `inputs` と最後の層の出す数) をデータに合わせるため
- **版 2 と版 3** (`form: items`. ML-EDA の `ITEMS_FORMAT_VERSIONS` の版): 受け持ち (`role`), 正解の種類 (`target.kind`), 項目ごとの種類, 入力か正解か, 単位, 書き出しでかけた中身の手順 (版 3 の `steps`. 手順と引数を `resize (width 64, height 64)` のように並べる. 推論で新しい 1 件に同じ手順をかけるため), 座標の決まり (撮影は深度の測り方 (`depth`. `z` はカメラの前の軸に沿った距離, `ray` は光線に沿った距離) と画素の中心 (`pixel_center`) を別の行に. 欄の無い撮影には, 書き出し直すと入ると出す), 分割ごとの件数と全ての件数, 正解の出どころ (`target.origin` の種類, 名前, 設定), 正規化をかけたか, 書き出しの注意 (`load_items`). 元の場所 (`source`. ML-EDA はディレクトリの名前だけを書く) は出さない. 出どころが `process` (今ある処理の出力) なら, 「測れるのはその処理との一致で, モデルはその処理を超えられない」と短く添える. 項目の種類は日本語の名前で出す (数の値, 種類の値, 画像, 領域など. 知らない種類は「その他の値」). 受け持ちが群分けの表 (`group`) のものは, ファイルの組でなく「群分けの表」と添え, 正解を「正解なし」と出し, 正解の出どころを出さない (正解を持たないため)
- **読めないもの** (`form: unreadable`): 知らない版 (版 1, 2, 3 の他) は「読めない版」として版の番号と理由を出す. 知っている版でも読めなければ, 理由を出す. `dataset.yaml` がデータセットのディレクトリの外を指すリンクなら, 版を読まずに理由を出す (ML-EDA の `load_items` と同じ決まり. ディレクトリ自体のリンクは信頼し, それもたどった後の場所と比べる). 一覧から黙って消さない. `dataset.yaml` の無いディレクトリ (書き出し途中の一時ディレクトリなど) はデータセットではないので並べない
- **並べる場所**: 置き場の `datasets` の下と, 「プロジェクトへ書き出す」で書き出した場所 (登録したデータに持つ `project_dataset`) と, ML-Pathfinder の置き場の問題の設定のプロジェクトの記録の場所 (`project.dataset`. ファイルの組の受け持ちは登録したデータを持たないため). どれも今もデータセットがあるものだけ. 同じ場所は 1 つにする. プロジェクトのものは `project` にデータか問題の設定の名前を, `project_from` にどちらか (`source` か `problem`) を持ち, 画面は「プロジェクト」と元の名前を添える (版 1 も版 2 も)

## 9. ファイルの組の書き出し

画像と領域の対, 多視点の撮影と正解の点群の対を, ML-EDA の版 2 の約束で書き出す (`export_image_masks`, `export_capture_clouds`). 表の手順をかけず, 1 件ずつのファイルに項目ごとの中身の手順だけをかける (手順が無ければファイルを写す. 撮影と点群は座標の正規化もかける) ので, 登録したデータとレシピを通さず, 2 つのディレクトリを選んで書き出す. 中身の手順をかけたデータセットは版 3 になる (ML-EDA が決める).

- 画面: データセットの一覧の「ファイルの組を書き出す」から移る. 「画像と領域」と「撮影と点群」をタブで切り替える. 版 1 の書き出し (前処理のタブの「保存と書き出し」) と同じく, データセットの名前と「同じ名前があれば置き換える」, 書き出す押しボタン, 書き出した場所と注意と使い方の例を出す
- ディレクトリ: 画像と領域 (それぞれ 2 階層まで. 名前の stem で組にする), 撮影 (撮影のディレクトリか, それを並べたディレクトリ) と点群 (直下の `<撮影の名前>.<拡張子>`). パスを書くか, 「選ぶ」でディレクトリをたどって選ぶ
- 設定: 分割 (自動 (グループがあればグループごと, 無ければ無作為), 無作為, グループごと, 分けない), 正解の無い件 (領域の無い画像, 点群の無い撮影) を除く (既定. 数と例を書き出しの注意に) か `unlabeled` の分割に書くか (ML-EDA の `split.unlabeled`. 除くは既定と同じなので渡さない. 選んだ方の扱いを欄の下に出す. 結果の分割では「unlabeled (正解なし)」と添え, 学習のスクリプトでの使い方に `dataset.split("unlabeled")` の読み方 (正解の項目は None) を足す), 検証用とテスト用の割合, 乱数の種. グループ (任意. 1 行に `件の id,グループ`. 撮影は現場や物で分ける), 正解の出どころ (種類, 名前, 設定 (YAML の辞書)). 画像と領域は値の名前 (1 行に `値: 名前`) と領域のファイルの名前の終わり (`mask_suffix`), 撮影と点群は点群の単位 (`cloud_units`)
- **中身の手順**: 入力と正解の項目ごとに, 1 件ずつのファイルにかける手順を並べる (`item_steps`. 大きさのそろわない画像を学習のコードで毎回そろえず, 推論でも同じ手順をかけられるように). 選べる手順は ML-EDA の手順の登録簿 (`ITEM_STEPS`) から項目の種類で絞ったもの (`GET /api/info` の `pair_steps`): 画像と撮影は `resize`, `grayscale`, `rgb`, 正解の点群は `sample_points`. 他の手順 (`normalize` など) はファイルの形に収まらず ML-EDA が受け付けないので出さない. 領域には ML-EDA が画像の `resize` と同じ大きさの `resize_mask` を自動でかけるので, 領域の欄は出さない. 手順は足した順にかける. 引数 (`width`, `height`, `points`, `seed`) は整数にし, 省けない引数 (登録簿の `required`) が無いか 1 未満 (`seed` は 0 未満) か上限を超えれば書き出す前に止める. 上限は画像の辺 (`width`, `height`) が 4096 画素, 点の数 (`points`) が 100 万点 (大きすぎる値で手元の計算機の記憶を使い切らないため. 版 1 の中身の手順と同じ `STEP_LIMITS`). 上限はバックエンドが持ち (`pair_steps` の `limits`), 画面と API の両方で確かめる. 手順を足さなければ版 2 で書き出す
- 結果: 書き出した場所, 件数, 書き出しの注意 (組にならなかったファイル, 分割をまたぐグループ, 0 件になった分割など. ML-EDA の `notes`), `load_items` で読む例. 書き出せない誤り (EXIF の向きの付いた画像, カラーの領域, 姿勢の無い撮影など) は理由を出して書き出さない
- グループと値の名前と設定の文は画面で辞書にし, 形が誤っていれば書き出す前に止める (書き出しの押しボタンを押せず, 理由を並べる). 欄を変えると前の結果と誤りを消す. タブを切り替えても入れた値は残す
- 書き出し (版 1 も) はアプリの中で 1 つずつ行う (同じ名前の一時ディレクトリを 2 つの書き出しが同時に使わないように). 壊れたファイル (読めない点群など) の誤りも理由を付けて 422 で返す
- **問題の設定から始めた場合**: 「問題の設定から始める」でファイルの組の受け持ちの問題の設定を選ぶと, この画面に問題の設定の場所を付けて移る (下の「11. 問題の設定から始める」). 正解の種類のタブだけを出し (もう一方は問題の設定に合わないため), 欄を ML-Quest の `recipe_from` の書き出しの設定の下書き (ディレクトリ, 分割, グループ, 正解の出どころ, 他の引数) で埋める. 名前の欄の代わりに書き出し先 (プロジェクトの記録の `project.dataset`) とその様子を出し, 「プロジェクトへ書き出す」で書き出す. 書き出し先の決まり (記録が要る, データセットでないものは置き換えない, 前のデータセットは置き換えの印を付けた場合だけ置き換える) は版 1 の「プロジェクトへ書き出す」と同じ. 書き出すと, 欄の値を ML-Quest の `apply_recipe` で問題の設定に書き戻す (`data.export`). 書き戻した点と注意の食い違いを結果に出す. 中身の手順も同じ欄で選び, 他の引数と一緒に書き出しの設定の `options.item_steps` に入れる (手順が無ければ入れない). 書き出しにかけ, 問題の設定にも書き戻すので, 開き直すと中身の手順の欄を `recipe_from` の `export.options.item_steps` で埋める (問題の設定から同じデータセットを作り直せるように)

## 10. 前処理の組み立て

- 左に目的とタスクと分割, 手順の並び (足す, 消す, 並べ替え, 引数を変える), 保存と書き出し. 右に手順をかけた前と後の表
- 保存していない手順 (編集中のレシピ) はデータごとにブラウザに覚え, タブを移っても, ページを読み込み直しても残す. 保存か書き出しをするか, 読み方を変える (手順が合わなくなる) と消す
- **分割**: 無作為, 層化, 時刻の順, グループごと, グループと時刻の組 (`group_time`. 同じ相手を 1 つの分割にまとめつつ, 後から現れた相手を検証用とテスト用に. 日時の列が要る), グループの層化 (`stratified_group`. 同じ相手をまとめつつ, 目的の値の割合をそろえる. 目的の列が要る), 分けないから選ぶ. グループの層化は, タスクが回帰か時系列の予測なら選べない (目的の値で層を作れないため. ML-EDA の `load_recipe` が止める). タスクを変えて残った場合は, 欄の下に誤りを出す (試した結果も ML-EDA の誤りになる). タスクを決めない場合に目的の値がほぼ全て違うときと, 日時の列や目的の列が無いときは, ML-EDA の誤りを試した結果の所に出す. 時系列で時刻の順を勧める「決めてほしいこと」は, グループと時刻の組を選んでいれば出さない (時刻の順に分けるため). グループの列 (会員の ID のように, 同じ人や物を表す列. ML-EDA のレシピの `split.column`) は, グループごと, グループと時刻の組, グループの層化では分ける単位になり (要る. 欄の空の値は「選ぶ…」), それ以外 (分けないを除く) では任意で選び, 同じ値が複数の分割にまたがるかを確かめる (ML-EDA の `group_overlap`. 時刻の順では参考, 他は注意). 欄を空にするか, 分けないにすると列の指定を消す. 画像は中身の同じファイルが分割をまたぐかを ML-EDA が確かめる (`item_overlap`. `digest` の列). これらの分割の後の気付きは, 学習用のデータの欄に重要度つきで出す (前処理の様子の API の `findings`). 時刻で分ける分割 (時刻の順, グループと時刻の組) を, 時刻の列の無い読み方 (表) で選んだ場合は, 日時に見える列 (日時の型か, よく出る値が全て日付か日時の文字の形の列) があれば, 欄の下に「読み方」を「時系列 (時刻: その列)」にする案内を出す (表として読むと日時の列を時刻に使わず, ML-EDA は「日時の列が要ります」とだけ止めるため)
- **正解の欠けた行**: 目的の列の欠けた行を, 落とす (既定) か `unlabeled` の分割に残すか (ML-EDA のレシピの `split.unlabeled: keep`) を選ぶ. 半教師あり学習や異常の検知のように, 正解の付いた行が少なく, 正解の無い行も学習に使いたい場合のため. 正解の付いた train, valid, test の中身は落とす場合と変わらない. 目的の列が無ければ欄を出さず (ML-EDA では誤りになるので, 目的の列を外したら, 前処理のタブを開いていなくても編集中のレシピ (無ければ保存したもの) から指定を消す. 目的の列を戻しても残すには戻らず, 保存するまで編集中の印が出る), 分析した全ての行で目的の列が欠けていなければ選べない (残すを選んでいる場合は戻せるように選べる). 落とすを選ぶと項目を消す (既定と同じで, 項目の無いレシピと見分けない). 分割の件数とデータセットの一覧では, `unlabeled` を「正解なし」と添えて並べる. 書き出した後の使い方の例は, ある分割 (valid, unlabeled) だけを読む
- 手順の番号を押すと, その手順の前と後を並べる (足した列と消えた列に色). 押していないときは全ての手順の後と, 学習用のデータ (分割ごとの行数, 学習に使う列の数, クラス, 学習の前に直すことの注意)
- **気付きから手順を足す**: 気付きに合う手順を足す (ID らしい列と定数の列を落とす, 欠損の多い列を埋める (数値は中央値, それ以外は最も多い値), 偏った分布の対数, 外れ値の切り詰め, 表記のゆれをそろえる (目的の列も), 同じ文を落とす, 空の文を除くなど). 画像, 文, 点群でも使える
- **学習できる形にする手順を作る**: 列の型から, 全ての列を数値にし欠損を無くす手順を作る (文, ID, 定数の列を落とす, 日時を分解, カテゴリをワンホットか番号付け, 欠損を埋める, 偏った数値の対数. 重複した行を落とし, 表記のゆれをそろえる. 時系列は, 数値の列 (目的の列も) の 1 つ前と, 自己相関で見つけた 1 周期前の値, 1 周期の移動平均の列を足し (店ごとのような複数の系列は, 系列を分ける列を符号化する前に `by` で系列ごとに. 系列を分ける列は, 値が 20 種類までならワンホット, それより多ければ番号付け), 過去が足りない始めの行を落とし, 時刻の列から曜日と月 (1 日より細かい間隔なら時と曜日) の列を足す. 最後に標準化)
- タスクを決めていないレシピは, 目的の列から推定したタスク (分類か回帰) で始める
- **決めてほしいこと**: 自動では決めきれないことを, 前処理のタブの先頭に選択肢付きのカードで出す. 押すとそのまま反映する (読み方, 目的の列, レシピ). 選んだ結果で当てはまらなくなったもの (分割を変えた, 中身の手順を作ったなど) は消え, 「このまま」と, 条件では消せない選択 (リークの疑いの列を落とすか残すか. 目的の列ごと) はブラウザに覚えて次から出さない. 残っている数は書き出しの欄にも出す. 今のカード:
    - 目的の列が無い: 名前と型から候補の列を出す
    - Excel に他のシートがある (読み込みの設定でシートを選んでいない): このままか, 他のシートを読むか
    - 表の中に文の列がある: 表のままでは落とすので, 文として読むか, 落としてよいか (文として読むと, 学習に使うのは文と目的の列だけになる)
    - 目的の列とほぼ同じ列 (リークの疑い. 時刻や系列のような役割の列は除く): 落とすか残すか
    - 時系列や分類で分割が合わない (時系列なのに時刻の順でない, クラスが偏るのに層別でない): 合う分割にするか
    - 時刻に抜けがあり, 行でずらす過去の値の列を足している: 抜けを挟むと 1 周期前が暦の 1 周期前にならない. このままか, 日付でずらすか (ML-EDA の lag の `time` と `freq`. freq は分析の時刻の間隔. 月や年のような 28 日以上の間隔は長さが変わるので出さない), 過去の値の列を外すか. どちらが良いかはデータによるので, 勧めは「このまま」にし, 学習で比べることを促す
    - 画像, 文, 点群, 音声で中身の手順が無い: 分析から作るか
    - 文の区切り方が, ML-EDA が比べて勧めるもの (下) と違う: 勧めに変えるか, このままか
- **文の区切り方**: 文のデータは, ML-EDA の分析 (`items.tokenizers`) が見本の文で文字, 語, 部分語を比べた結果 (語彙の大きさ, 1 つの文のトークンの数, 語彙に無い語の割合, 勧める長さ) を中身の手順の欄に表で出す. 行の「使う」で vocabulary をその区切り方にする. 「学習用の配列にする手順を作る」は勧めた区切り方を使う
- **中身の手順** (画像, 文, 点群, 音声): 表の手順の後に, 1 件ずつの中身を同じ形の配列にする手順 (item_steps) を並べる. 「学習用の配列にする手順を作る」で分析の結果から作る (画像は最も多い大きさに resize, 色の形式が混ざれば rgb, normalize. 文は ML-EDA が比べて勧めた区切り方と長さの vocabulary (比べた結果が無ければ, 語数の第 3 四分位の 1.5 倍の長さ). 点群は点の数の中央値 (1024 まで) の sample_points と normalize_cloud. 音声は最も多い標本化の周波数の resample, 最も多いチャンネルの数の mix_channels, 長さの中央値 (0.01 秒に丸め, 30 秒まで) の fix_length (この順は ML-EDA の設計の順). 周波数などがそろっていても足す (推論で読む新しい 1 件も同じ形にするため. 画像の resize と同じ)). 選べる手順と引数の欄は ML-EDA の手順の登録簿 (`ITEM_STEPS`) の, その種類のもの (`GET /api/info` の `item_steps`). 読めない件があれば, 表の手順の先頭に filter_rows (画像は width が notna, 点群と音声などは error が isna) も足す. 画像などは, 中身を読まずに (`prepare(..., read_items=False)`) 中身の手順を確かめ, 読めない件や大きさ, 色の形式, 点の数, 音声の周波数とチャンネルと長さのばらつきの注意と分割の件数とクラスを出す (全ての中身は書き出しのときに読む). 写真のような大きな画像は長い辺を 224 までに縮め, 比べた結果が無い場合の空白で区切らない文は文字ごとの語彙にする. 中身の手順の引数の上限 (`STEP_LIMITS`) は, 手順を中身にかける全ての経路 (数件で試す (`item_preview`), 書き出し, プロジェクトへの書き出し, ファイルの組の書き出し) で, かける前に API で確かめ, 超えれば手順の番号と入れた値を添えて 422 で止める. 上限はバックエンドが持ち (`GET /api/info` の `item_steps` の `limits`), 版 1 の中身の手順の欄でも, 上限を超えた値に手順の番号と上限を添えた理由を出し, 「数件で試す」と書き出し (プロジェクトへの書き出しも) を押せなくする (送る前に分かるように. ファイルの組の書き出しの欄と同じ). 同じ名前の引数は, どの手順でも同じ上限にする (手順ごとに覚えずに済むように). 上限は画像の辺 (`width`, `height`) が 4096 画素, 点の数 (`points`) が 100 万点, 音声の標本化の周波数 (`rate`) が 192000 Hz, 長さ (`seconds`) が 600 秒, チャンネルの数 (`channels`) が 32, 語彙の大きさ (`max_tokens`) と文の長さ (`length`) が 65536 (大きすぎる値で手元の計算機の記憶を使い切らないため. 192000 Hz は録音の機器の高い側の周波数. 両方が上限の 1 チャンネルの音声は 1 件で約 460 MB の 32 ビットの数になり, これより大きいと数件の見本 (8 件で約 3.7 GB) だけで手元の記憶を使い切りかねない). 600 秒より長い録音は, 前もって 600 秒以下のファイルに分けてから読み込む. 入力が長い音声は, `fix_length` を `resample` の前に置くと, 周波数を変える前に短くするので記憶を減らせる
- **中身の手順の前と後** (画像, 文, 点群, 音声): 「数件で試す」で, 学習用の少ない見本 (100 件) で当てはめた中身の手順を, 学習用から選んだ 8 件にかけた前と後を出す (`POST /api/sources/{id}/item_preview`. ML-EDA の `preview_items`). 画像は並べ, 文は語に戻した番号の並び, 点群は 2 つの 3D 表示, 音声は選んだ 1 件の前と後の再生と波形 (どちらも先頭の 5 秒. 何件も返すので「中身を見る」より短く. 再生用の音は WAVE の data URL で返す. 後の周波数は最後の resample の rate)
- 画像, 文, 点群, 音声のディレクトリは, クラスのフォルダの名前の label を目的の列にして登録する
- 書き出すと, ML-Found の学習スクリプトで読み込む例と, モデルを組むときの数 (1 件の入力の形と型, 出力の幅 (目的の無いデータセットでは出さない), 文の語彙の大きさ (埋め込みの数. ML-EDA が書き出したレシピの最後の `vocabulary` から求める) は ML-EDA の `model_inputs` から. 書き出しの API の `hints`) を出す. ML-CreateArchitecture のモデルとは自動でつながないので, 部品の引数に合わせる数を示す

## 11. 問題の設定から始める

問題の設定の段階 (ML-Quest と画面の ML-Pathfinder) で決めたことを入れた状態で始め, ここで変えた選び方を問題の設定に書き戻す (段階どうしのつなぎ目の誤りを早く見つけるため). 「データを追加」から入れる流れも使える.

- **始める**: データの画面の「問題の設定から始める」で `problem.yaml` (か, それを持つディレクトリ) を選ぶ. ML-Quest の `recipe_from` で, データの場所と読み方 (問題の設定に入れたデータ. 写しが消えていれば元の場所) と, レシピの雛形 (目的の列, タスク, 使わない列を落とす手順, 時系列なら決める時点で分かる期からの系列ごとの過去の値, 分割と, あれば相手をまとめるグループの列) を受け取り, データを登録してレシピを保存する (列の予測. 画像か表の生成とファイルの組の受け持ちは下の「受け持ち」). 問題の設定の場所と, `recipe_from` の知らせ (`notes`) は登録したデータに持つ (`problem`, `problem_notes`). 知らせは「問題の設定」のカードの「始めたときの知らせ」に出し続ける (始めた後に直すことを, 前処理を組み立てる間に見られるように). 問題の設定を渡せない (直すところがある) か, データを入れていなければ, 理由を出して登録しない
- **食い違いを見る**: 問題の設定から始めたデータでは, 前処理のタブの先頭に「問題の設定」のカードを出す. 編集中のレシピを ML-Quest の `apply_recipe` で試しに書き戻し (保存はしない), 変わる点 (目的の列, タスク), 食い違い (使ってはいけない列を使う (誤り), 決める時点で分からない期の過去の値, 相手をまとめる列とレシピのグループの列の違い, 時系列なのに時刻の順でない分割 (注意)), 選ぶ問い (予測の時点で分からない列をレシピで使っている: 分かる列に移すか, レシピで落とすか) を出す. まとめるで学習する受け持ちの問題の設定から始めたデータは, 確かめをせず, カードにレシピを持たない理由を誤りでなく案内として出し, 群分けのタブへのリンクを置く (下の「14. 群分けの表の分析」)
- **書き戻す**: 選ぶ問いに全て答え, 誤りの食い違いが無ければ「問題の設定に書き戻す」を押せる. ML-Quest の `apply_recipe` と `resolve_choice` で問題の設定を直して元の場所に保存し (レシピも問題の設定の `data.recipe` に持つ), 落とすと選んだ列を足したレシピをここにも保存する. 列の使い方は方針なので, 自動では変えず必ず選ばせる
- **問題の設定の一覧**: 「問題の設定から始める」の上に, ML-Pathfinder の置き場 (上の「6. 置き場」) にある問題の設定を, 更新の新しい順に並べる (名前, 場所, 更新時刻). 押すとその問題の設定を選ぶ. 始められないもの (列の予測, 画像か表の生成, ファイルの組の受け持ち, 並べるかまとめるで学習する受け持ちのどれでもない, 列の予測か画像か表の生成か並べるかまとめるでデータを入れていない, 並べるかまとめるで骨組みを書き出せない, 読めない) も理由を付けて並べる (黙って消さない). 置き場の外のものは, 下のファイルの選び方で選ぶ
- **プロジェクトへ書き出す**: 始めた問題の設定に ML-Quest のプロジェクトの記録 (`project.dataset`. 学習のスクリプトがデータセットを読む場所) があれば, 書き出しの欄に「プロジェクトへ書き出す」を出す. 書き出し先は記録のまま (名前を選ばない). 学習のプロジェクトへ手でファイルを写さずに渡すため
    - 書き出し先に前に書き出したデータセットがあれば, 置き換えてよいかを確かめてから置き換える. データセットでないもの (`dataset.yaml` の無いディレクトリやファイル) は置き換えない (ML-EDA の書き出しの決まりと同じ)
    - 記録の `project.path` と `project.dataset` は絶対パスで, 両方が要る. プロジェクトのディレクトリ (`project.path`) が無ければ書き出さない (消したか動かしたプロジェクトの場所に作らないように). 書き出し先はプロジェクトの中に限る. 外の絶対パス, `..` で外に出る場所, 途中のシンボリックリンクをたどると外に出る場所と, プロジェクトのディレクトリそのものは, 置き換えの印を付けても理由を付けて 422 で断る (ML-Quest の骨組みは書き出し先をプロジェクトの中の `outputs` か `data` に置くので, 外を指すのは手で書き換えた記録. 問題の設定のファイルの書き換えで, 手元の思わぬファイルを置き換えないため). 中の親のディレクトリは無ければ作る. 書き出し先がシンボリックリンクなら, 先がデータセットでも置き換えない. これらの確かめは書き出しと同じ鍵の中で行う
    - 記録が無い問題の設定 (プロジェクトをまだ作っていない) では, ボタンの代わりに「ML-Pathfinder でプロジェクトを作ると書き出せる」と出す
    - 書き出すとレシピも保存し, 書き出した場所を登録したデータに持つ (データセットの一覧に並べるため). 結果はいつもの書き出しと同じく, 場所とモデルを組むときの数を出す
- 問題の設定のファイルが消えたか読めなければ, カードに理由を出す (データの分析は続けられる)
- 問題の設定のファイルであること (名前と作った時刻を持つ) と, 始めたときと同じ問題の設定 (作った時刻が同じ) であることを確かめてから読み書きする (レシピなど別の YAML を上書きしないように). 書き戻すときは, 確かめたときのファイルの中身の印 (sha256. 必須) を送り返し, 読む前と保存の直前に比べて, 違えば (ML-Pathfinder などで変えた) 書き戻さない (画面は確かめ直す). 書き戻した問題の設定が後ろの段階に渡せること (ML-Quest の `handoff`) と, できたレシピを前処理にかけられることも確かめる
- 画面は, 確かめが最新の編集に追いつくまで書き戻しを押せないようにし, 書き戻すのは待つ前の最新のレシピ
- **問題の設定の版**: ML-Quest の問題の設定の版 1 と版 2 を読む. 版 1 は ML-Quest の `load_problem` が読んだ後に版 2 に移す (`upgrade_problem`) ので, この画面は版 2 だけを扱う. 書き戻すと版 2 で保存する (ML-Quest の `save_problem`. ファイルは書き戻すまで版 1 のまま). 食い違いの場所は版 2 の名前 (`ml.parts.0.available_lag` など)
- **受け持ち**: 始めるのと書き戻しは, 列の予測 (受け持ちが予測する (`predict`) で, 正解の種類が表の列 (`column`)) と, 画像か表の生成 (作る (`generate`) で, 正解の種類が画像 (`image`) か表 (`table`)) と, ファイルの組の受け持ち (予測するで, 正解の種類が画像の領域 (`mask`) か点群 (`point_cloud`)) (ML-Quest の `recipe_from` と `apply_recipe` と同じ). 並べるで学習する受け持ち (並べる (`rank`) で, 作り方が既製のモデルをそのまま (`pretrained`) でない. ML-Quest の並べるの骨組みと同じ決まり) は始めることだけで, 書き戻しは無い (下の「13. 並べるの反応の表の分析」). まとめるで学習する受け持ち (まとめる (`group`) で, 作り方が既製のモデルをそのままでない. ML-Quest のまとめるの骨組みと同じ決まり) はレシピを持たず, 群分けのタブの選び方を ML-Quest の `apply_group` で書き戻す (下の「14. 群分けの表の分析」). 受け持ちの見分けは ML-Quest の公開の関数 (`is_column_part`, `is_items_part`, `active_value`) で行う. 他の受け持ち (効果を見積もるなど) と正解の種類 (文など), 既製のモデルをそのまま使う予測と並べるとまとめるの問題の設定は, 使えない受け持ちと正解の種類 (画面の選択肢と同じ言葉と値. 「効果を見積もる」(effect) など), 使えない理由 (方策は環境とのやり取りで集めるのでデータの分析の段階を通らない, など), 使える受け持ち, 「データを追加から入れて分析できる」ことを 422 で返す (画面は理由を出す). 始めた後に問題の設定の受け持ちが変わった場合の確かめと書き戻しも同じ
- **画像か表の生成**: 目的の列が無いので, 列の予測と同じく入れたデータを登録し, ML-Quest の雛形の目的の列の無いレシピ (`task: none`, 手順は空, 無作為の分割) を保存する. 登録する前に, データの種類 (ML-EDA の読み込んだデータの `kind`) が作るものに合うこと (画像は `image`, 表は `table` か `timeseries`. 日時の列を見つけた表は `timeseries` になるが, 中身は表のため) を確かめ, 合わなければ作るものとデータの種類の文を 422 で返して登録しない. 食い違いの確かめと書き戻しと「プロジェクトへ書き出す」は列の予測と同じ流れで, 書き戻すとレシピ (画像の中身の手順 `item_steps` も) を問題の設定の `data.recipe` に持つ. ML-Quest の骨組みは, プロジェクトの記録の場所 (config の `data.dataset`) から, 目的の列の無い版 1 のデータセット (種類が `image` か `table`, 検証用の分割付き. 表は学習に使う列に欠損が無いこと) を読むので, 書き出しはその形になる (目的の列を書いたレシピと, 検証用の分割の無いレシピは, ML-Quest の食い違いとしてカードに出す)
    - 画像の生成は, ファイルの組の書き出しの画面を使わない. 骨組みが読むのは画像のディレクトリを `image_folder` で読んだ版 1 のデータセットで, ファイルの組の書き出し (版 2 と版 3) は正解のディレクトリと組にした別の形のため. 大きさをそろえる `resize` などの中身の手順は, 前処理のタブのレシピの中身の手順で選ぶ
- **ファイルの組の受け持ち**: データを登録せず (正解が表の列でなく, 版 2 の書き出しは登録したデータとレシピを通さないため), ファイルの組の書き出しの画面 (上の「9. ファイルの組の書き出し」) に問題の設定の場所を付けて移る. データを入れていない問題の設定も始められる (ディレクトリは画面で選ぶ). 画面を開くたびに問題の設定を読み直し, 下書き (書き戻した設定があればそれ) で欄を埋める
    - 書き出しは, 確かめたときの問題の設定の中身の印を送り返し, 書き出す前に比べる. 書き出しの設定の形の誤りは 422, ML-Quest の食い違いの誤り (正解の種類に合わない書き出し, グループの無いグループごとの分割) は 409 で書き出さない. 入力と正解のディレクトリが無ければ 422
    - 書き出した後, 保存の直前にもう一度中身の印を比べ, 違えば (ML-Pathfinder などで変えた) 書き戻さずに 409 で「書き出したが書き戻していない」と返す (画面は開き直して書き出し直す)

## 12. 記録した軌跡の分析

強化学習の方策を走らせた軌跡 (ML-Found の評価の軌跡と, 同じ列を持つ手元の表) を, 登録したデータの 1 つとして分析する. 読み込みと要約は ML-EDA の `load_trajectory` と `describe_trajectory` が行い, このアプリは要約を画面に並べて書き出すだけを受け持つ (表の分析と同じく, 分析の仕組みを ML-EDA に置くため).

- **登録**: 「データを追加」で選んだファイル (表 `.csv`, `.parquet` か説明 `.json`) が `load_trajectory` で読めれば, 読み込みの候補の先頭に `trajectory` (種類 `trajectory`) を足す (軌跡の表は普通の表としても読めるので, 表の候補も残す). 読む前に見出しだけを確かめ, 合わなければ読まずに候補から外す (軌跡でない大きなファイルを, 候補を出すためだけに全て読まないように). CSV は 1 行目, Parquet はスキーマ (pyarrow) の列の名前に `episode` と `step` があるか, JSON は先頭 (64 KiB) が辞書で `format_version` と `file` の鍵を含むか. 候補を出すときに読んだ要約は覚えて, 登録と画面でそのまま使う (同じファイルを何度も読まないように). 同じ軌跡を表 (`foo.csv`) と説明 (`foo.json`) の両方から登録してもよい (別のデータとして並ぶ. 中身は同じ要約) 読み込みの設定と目的の列は持たない. 登録するときに読めることを確かめ, 読めなければ ML-EDA の理由を 422 で返す
- **読み直し**: 要約は, 登録した場所と, 同じ名前の `.csv`, `.parquet`, `.json` の更新時刻ごとにメモリに覚える (表を登録した後に隣の説明を書き換えても読み直すように)
- **表の分析は使わない**: 軌跡のデータには, データを表として読む API (分析, 表の中身, 前処理の前と後, 書き出しなど) は 422 を返し, 画面もそれらのタブを出さない (`load_data` は軌跡を普通の表として読み, 守りで止めた行の空と nan を分けないため)
- **画面**: データごとの画面で, 表のタブの代わりに次のタブを出す. 値は全て `describe_trajectory` の結果をそのまま使う
    - **概要と気付き**: エピソード, 行, 環境を進めた歩数, 長さと報酬の和の平均, 守りの有無, 行動を選んだ確率の列の有無. 読むときと要約で気付いたこと (`notes`). エピソードの長さと報酬の和の要約 (平均, 標準偏差, 最小, 中央値, 最大. 全てのエピソードで求めたもの) とヒストグラム (`per_episode` から描く. 切った場合は先頭の 1000 件で描いたと添える. 区間は値の数の平方根 (20 まで) の同じ幅で, 値の範囲 (最大 - 最小 + 1) が 20 以下の整数は 1 つの値を 1 つの区間にし, 区間の見出しを値にする. 全て同じ値なら範囲を ±0.5 に広げる), 和が有限でないエピソードの数 (`unknown_returns`), 終わり方ごとのエピソードの数 (`ends`), 説明の項目 (出どころ (`source`. ML-Found の書いた英字の名前でなく, 評価の loader, 守り付きの評価のような日本語の言い換えで出す. 知らない値はそのまま), 環境, エポック, 観測と行動の空間など) と, 観測, 行動, その他の列 (`extra_columns`)
    - **観測と行動**: 要素ごとの欠け (`missing`), nan (数でない値), 無限大の数と, 有限の値の最小, 最大, 平均, 標準偏差, 中央値. 欠けは ML-EDA の `missing` を出す (nan は値で, 欠けと分けて数えるため). 値ごとの数 (`counts`. 整数の列で異なる値が 50 以下) のある行動は横棒グラフで描く (Discrete の行動の偏り). 他 (Box の行動) は要素ごとの統計だけ. 行動を選んだ確率の列 (`action_prob`. ML-EDA の `with_action_prob` と `action_prob`) があれば, 欠けの数, 範囲 (0 より大きく 1 以下) の外の数と, 範囲の中の値の最小, 最大, 平均, 中央値. 無ければ無いと出す
    - **守り** (守りの列のある表だけ): 結果ごとの行の数の横棒グラフ (結果は英字でなく日本語の名前で出す: そのまま通した, 範囲に収めた, 代わりの行動にした, 止めた, 引き継いだ, 空. 知らない結果は「その他 (値)」) と, 働いた理由ごとの行の数の表 (多い順)
    - **エピソード**: エピソードごとの行の数, 長さ, 報酬の和, 終わり方, 乱数の種 (`per_episode`). エピソードが 1000 件を超えて切った場合 (`per_episode_truncated`) は, 全ての数と並べた数を添えて知らせる
- **書き出し**: 「分析を書き出す」で, 要約をそのまま JSON (`<軌跡の名前>.analysis.json`. 名前のパスに使えない文字は `_` に) としてブラウザで保存する. 置き場には書かない (データセットではなく, 元のデータの読み直しで同じ要約を作れるため)

## 13. 並べるの反応の表の分析

並べる (推薦) の問題の設定に入れた反応の表を, 問題の設定で答えた列 (ML-Quest の `ml.parts.<n>.rank` の `user`, `item`, `time`, `reaction`) で読み, 偏りと除く行を見てから, 並べるの骨組みが読む場所に写す. 読み込みと要約は ML-EDA の `load_reactions` と `describe_reactions` が行い, このアプリは要約を画面に並べて写すだけを受け持つ (除く行の決まりを ML-EDA と ML-Quest の骨組みにそろえ, 画面の数と学習の `train.log` の数を合わせるため).

- **始める**: 「問題の設定から始める」で並べるで学習する問題の設定を選ぶと, 入れた反応の表 (写しが消えていれば元の場所) を, 問題の設定の手元のデータの読み方 (`data.loader` と `data.options`. 読み込みが無ければ ML-EDA の候補の先頭) で読み, 種類 `reactions` のデータとして登録する (骨組みの学習のスクリプトと同じ読み方にするため). ML-Quest の `recipe_from` は並べるを扱わないので使わず, レシピも保存しない. ML-Quest の `project_error` で骨組みを書き出せない (出力の形が順位でない, 入れたデータが表でない, 直すところがある) か, データを入れていないか, 反応の表がファイル 1 つでないか, 問題の設定の列で反応の表として読めない (列が無い, 時刻が数でも日時でもない) 場合は, 理由を 422 で返して登録しない. 一覧の始められるかと理由も同じ確かめ
- **要約**: 要約を出すたびに問題の設定を読み直し, その列で, 読み込み済みの表 (`Data`) を `load_reactions` に渡す (読み直さない). 始めた後に受け持ちが並べるでなくなった場合と, 答え直した列が表に無い場合は 422
- **表の分析とレシピは使わない**: 反応の表の画面は表の分析のタブを出さず, レシピの確かめ, 書き戻し, レシピでの書き出し (`export_project`) は 422 で断る. 並べるは反応の表をデータセットにせず, 分割は骨組みが時刻で行うため (ML-EDA の「並べるの反応の表」の「分割は持たない」)
- **画面**: データごとの画面で, 表のタブの代わりに次のタブを出す. 値は全て `describe_reactions` の結果をそのまま使う
    - **概要と気付き**: 反応 (除いた後の行), 除く前の行, 除いた行, 利用者, 品物, 利用者と品物の組の数, 密度, 並べる件数 (K). 読むときと要約で気付いたこと (`notes`). 読んだ列 (反応の強さの列が無ければ全ての行を反応とみなすこと), 除いた行の内訳 (欠け, そのうち日時として読めない時刻, 強さが 0 以下か数でない), 時刻の種類 (数か日時) と範囲と異なる時刻の数, 反応の強さの要約 (列があれば)
    - **偏り**: 品物の人気の偏り (上位 10% の品物の数とその反応の割合, ジニ係数, 同じ組の 2 行目からの数) と, 反応の多い品物の先頭 10 件の表. 利用者ごとと品物ごとの反応の数の要約 (平均, 標準偏差, 最小, 中央値, 最大, 1 回だけの数) と, 区切りごとの数の横棒グラフ
    - **表の中身**: 表の中身のタブと同じ (元の表のまま)
    - **書き出し**: 下
- **プロジェクトへ書き出す**: 反応の表を前処理せず, ファイル 1 つのまま, 問題の設定のプロジェクトの記録の書き出し先 (`project.dataset`. ML-Quest の骨組みの config の `data.dataset` で, データを入れた問題の設定では `data/` の写し) に写す. 骨組みは問題の設定の読み方で `load_data` で読み, 時刻で分ける
    - 写す前に, 今の問題の設定の列で反応の表として読めることを確かめ, 結果に骨組みが反応とみなす行の数と除く行の数を添える
    - 書き出し先に前に置いたファイルがあれば, 置き換えてよいかを確かめてから置き換える (骨組みを作ると入れたデータを写すので, 初めから置いてあることが多い). ファイルでないもの (ディレクトリ, シンボリックリンク) は置き換えない. 書き出し先と反応の表の拡張子が違えば写さない (読み込みを決めていない読み方は拡張子で候補が変わるため). 書き出し先が登録した表そのものなら写さない
    - 写すのは同じディレクトリの一時ファイルに写してから置き換える (途中で止まっても前のファイルを壊さないように). 記録とプロジェクトの確かめ (上の「11. 問題の設定から始める」の「プロジェクトへ書き出す」) と置き換えてよいかの確かめは, 写しと同じ鍵の中で行う
    - 書き出したファイルはデータセットではないので, データセットの一覧には並ばない

## 14. 群分けの表の分析

群分け (まとめる) の課題の, 正解の無い 1 行が 1 つの対象の表 (客, 店, 品物など) を, 登録した表のまま分析し, 学習に通さずに群を作って群の要約を見てから, 学習のプロジェクトへ表のファイルを渡す. 書き出しは 2 つあり, カードの名前と説明の文で使い分けを示す. 学習のプロジェクトへ渡すのは「プロジェクトへ書き出す」(表のファイル. ML-Quest のまとめるの骨組みが `load_data` で読む形) だけ. 「群分けの表を分析用に書き出す」(版 2) は分析の保存 (読み直して群の要約を求める) で, 骨組みは読まない (ML-Quest のまとめるの骨組みは, 並べるの骨組みと同じく表のファイルを `load_data` で読み, 分割も骨組みが行うため. ML-EDA の「群分けの表」の決まり). カードの説明は初めての利用者に向け, 何のための書き出しかと, 学習には「プロジェクトへ書き出す」を使うことを先に書く. 群の要約と書き出しは ML-EDA の `describe_groups` と `export_group_rows` が行い, このアプリは列と群の数を選ぶ画面と, 要約を並べる表だけを受け持つ (群の作り方と要約の形を ML-EDA と ML-Quest のまとめるの骨組みにそろえ, 分析の段階の群と学習の後の群を同じ表で比べられるようにするため).

- **どのデータで**: 種類が表か時系列のデータ (ML-EDA の `describe_groups` が読むもの). データごとの画面の「群分け」のタブで行う. 表の分析 (概要, 列, 関係など) はそのまま使える. 読み込み済みの表 (`Data`) を渡し, 読み直さない
- **群を作る列**: 列の一覧から選ぶ. 初めは, 型が ID, 文, 日時, 定数, 空の列と目的の列を外した列を選ぶ (行を見分ける列や値が 1 つの列は群を作る力が無く, 文と日時は別の扱いが要るため. 外した列も選べる). 1 つ以上選ばなければ作れない
- **群の数と乱数の種**: 群の数は 2 から 50 の整数 (k-means を置き方を変えて繰り返し, 作り直して安定性も数えるので, 大きな数で手元の計算機を長く使わないように. 上限は画面と API の両方で確かめ, 同じ値を両方に持つ). 乱数の種は 0 以上の整数 (既定 0)
- **安定性の数え方**: 問題の設定から始めたデータでは, 問題の設定の答え (`group.stability`) の数え方で数える (種を変える `seed` か, 標本を変える `sample`. ML-EDA の `describe_groups` の `stability`). 問題の設定から始めないデータ, 答えていない場合, まとめるでなくなった場合と, 問題の設定を読めない場合 (読み直しが失敗した場合も, 前に読んだ答えを使わない) は `seed`. 問題の設定を読み直している間は, 古い答えの数え方で作らないように「群を作る」を押せず, 理由を出す. 引く割合 (`fraction`) は問題の設定に答えが無いので送らず, ML-EDA の既定 (骨組みの config の `group.fraction` の既定と同じ 0.8) を使う. タブでは選ばない (骨組みは問題の設定の答えで数えるので, 選べると答えと違う数え方の値を骨組みと比べてしまうため. 欄と答えの違いの知らせと書き戻しも, 数え方を扱わない). 答えが変わると欄と同じく群の要約を消す
- **群の要約**: 群の数, 行, 調整ランド指数 (作り直した群との一致の平均と最も低い回), シルエット係数 (群のまとまり) と, 2 つの指標の意味 (調整ランド指数は, 返した数え方 (`stability.method`) に合わせて, 種を変えて作り直したか, 種を変えて行の一部 (`stability.fraction` の割合) を引き直して作り直したかを出し, 1 で全く同じ分かれ方, 0 で偶然と同じ程度. シルエット係数は -1 から 1 で, 1 に近いほど同じ群の行どうしが近い). 気付き (`notes`). 群の要約の表 (群, 行, 割合, 安定性 (Jaccard 係数の平均) と群を作った列ごとの平均か最も多い値. 最後に全体の行). 群を作った列 (数の列と種類の列の分け方), そろえた後の列の数, 乱数の種. 群の番号は ML-EDA の番号 (0 から) のまま「群 0」のように出す (学習の後の群の要約と同じ番号で比べるため). 内部の英字の名前 (`kmeans` など) は出さない
- **選び方を変えたら**: 列, 群の数, 乱数の種を変えると, 前の群の要約を消す (どの選び方の群かを取り違えないように)
- **群分けの表を分析用に書き出す**: 分析の保存で, 学習には使わない (カードの説明に, 学習のプロジェクトへは「プロジェクトへ書き出す」で表のファイルを渡すと書く). 群を作る列 (群の要約と同じ選び方) と, 行を見分ける列 (任意. 群を作る列の他から選ぶ. 選んだ後でその列を群を作る列に入れると「なし」に戻し, 送る値も見せる値にそろえる. 無ければ行の位置) を, 置き場の `datasets` の下に版 2 で書き出す (`export_group_rows`). 群の数は書かない (群の要約を求めるときに決める). 分割は無作為 (学習用と検証用. 検証用の割合を選べる. 既定 2 割) か分けない. 版 1 の書き出しと同じく, データセットの名前と「同じ名前があれば置き換える」を持ち, 書き出しはアプリの中で 1 つずつ行う. 結果に, 書き出した場所, 書き出しの注意 (ML-EDA の `notes`), `load_items` で読み直して `describe_groups` で群の要約を求める例 (群の数は書き出したときの値) を出す. 上の群を作る列か群の数を変えると, 書き出しの結果を消す. 書き出したものはデータセットの一覧に版 2 の群分けの表として並ぶ
- **問題の設定から始める**: 「問題の設定から始める」でまとめるで学習する問題の設定を選ぶと, 入れた表 (写しが消えていれば元の場所) を, 問題の設定の手元のデータの読み方 (`data.loader` と `data.options`) で読んで登録し, 群分けのタブを開く (骨組みの学習のスクリプトと同じ読み方にするため). 種類は読み込みのまま (表か時系列) で, 表の分析のタブもそのまま使える. 目的の列は持たない. ML-Quest の `recipe_from` はまとめるを扱わないので使わず, レシピも保存しない (群分けは表をデータセットにせず, 分割は骨組みが行うため). レシピの確かめ, 書き戻し, レシピでの書き出しは 422 で断る. ML-Quest の `project_error` で骨組みを書き出せない (出力の形が群でない, 入れたデータが表でない, 直すところがある) か, データを入れていないか, 表がファイル 1 つでないか, 表か時系列として読めないか, 答えた群を作る列か行を見分ける列が表に無いか, 骨組みが使えない名前 (下の「プロジェクトへ書き出す」) の場合は, 理由を 422 で返して登録しない. 一覧の始められるかと理由も, 読む前に分かる確かめ (骨組みを書き出せるか, データを入れたか) は同じ
- **問題の設定の答え**: 群分けのタブは, 開くたびに問題の設定を読み直し, 群を作る列, 行を見分ける列, 群の数を問題の設定の答え (ML-Quest の `ml.parts.<n>.group`) で埋める (表に無い列は外し, 範囲の外の群の数はそのまま出して理由を出す). 問題の設定のカードに名前と場所と答え (安定性の数え方も) を出し, 欄 (群を作る列, 行を見分ける列, 群の数) を答えと違う選び方にすると, 骨組みは問題の設定の答えで群を作ることを知らせ, 下の「問題の設定に書き戻す」を出す. 行を見分ける列の欄は「群分けの表を分析用に書き出す」の欄と同じもの (書き出しと書き戻しで行の見分け方を取り違えないため). 安定性の数え方が標本を変える (`sample`) なら, ここの調整ランド指数も標本を変えて数えることと, 骨組みは学習用の行から引くがここは全ての行から引くことを添える (分析の段階では学習用と検証用に分けないため). 始めた後に受け持ちがまとめるでなくなった場合は, 答えで埋めず, カードにそう出す
- **問題の設定に書き戻す**: 欄が答えと違う間, 問題の設定のカードで, 欄の選び方 (群を作る列, 行を見分ける列 (「なし」は外す), 群の数) を ML-Quest の `apply_group` で試しに書き戻し (`group_problem/check`. 保存はしない), 書き戻すと変わる点 (ML-Quest の変えた点の文. 書き出したプロジェクトがあれば, 骨組みを書き出し直す案内も) を出す. 安定性の数え方はタブで選ばないので送らない (書いた鍵だけが書き戻るため). 「問題の設定に書き戻す」で, 確かめたときの中身の印とともに書き戻して `save_problem` で保存し (`group_problem/write`), 問題の設定を読み直す (前処理のタブのレシピの書き戻しと同じ流れ). 読み直した答えは欄と同じなので知らせと書き戻しは消え, 欄と群の要約はそのまま残す (自分の書き戻しで欄を埋め直さないため). `apply_group` が断る選び方 (骨組みを組めない名前, 群を作る列と行を見分ける列の重なり, 使えるデータに無い列など) は, 書き戻さずに理由を付けて 422 で返し, 画面はその理由を出す. 確かめた後に問題の設定が他で変わっていれば 409 で断って確かめ直す. 書き出したプロジェクトの config は変わらないので, 書き戻した後は ML-Pathfinder で骨組みを書き出し直す
- **前処理のタブ**: まとめるで学習する問題の設定から始めたデータでも前処理のタブは開けるが, 「問題の設定」のカードは確かめ (`problem/check`) をせず, レシピを持たない理由 (骨組みは表をファイル 1 つのまま読み, 分割も骨組みが行う) を案内として出し, 群分けのタブへのリンクを置く. 「プロジェクトへ書き出す」も出さない (プロジェクトへは群分けのタブから写すため). 受け持ちは, 開くたびに `GET /api/sources/{id}/group_problem` の答え (`group`) の有無で見分ける (始めた後に答え直しても合うように). 前に読んだ答えは使わず, 読み終えるまでと読み直す間 (画面に戻ったときなど) は, 確かめのカードと「プロジェクトへ書き出す」を出さず, 確かめも呼ばない (前の答えのまま確かめの 422 を出さないため). 読めなければ, 今までどおり確かめのカードが理由を出す. 確かめの API の 422 は, レシピを送る呼び手への守りとして残す (分ける所を画面にし, API の約束を変えないため). 並べるの問題の設定から始めたデータは種類が反応の表で, 前処理のタブを出さないので当たらない
- **プロジェクトへ書き出す**: 表を前処理せず, ファイル 1 つのまま, 問題の設定のプロジェクトの記録の書き出し先 (`project.dataset`. ML-Quest の骨組みの config の `data.dataset` で, データを入れた問題の設定では `data/` の写し) に写す. 骨組みは問題の設定の読み方で `load_data` で読み, 群を作る列と行を見分ける列だけを使い, 学習用と検証用に無作為に分ける. 学習のプロジェクトへ渡すのはこの書き出しだけで, カードの説明にそう書く. 版 2 の群分けの表 (上の「群分けの表を分析用に書き出す」) は分析の保存で骨組みが読む形でないので, プロジェクトへは書き出さない
    - 写す前に, 今の問題の設定の答えの列が表にあり, 群を作る列の名前が ML-Quest の `GROUP_TAKEN` (群の要約の鍵と 1 件の決まった鍵. `group`, `rows`, `share`, `stability`, `id`, `split`) に無く, 行を見分ける列の名前が `GROUP_ASSIGNED` (群の割り当ての表の他の列. `group`, `split`) に無いことを確かめ, 始めるときと同じ ML-Quest の確かめ (`project_error`) に誤りが無いことも確かめる (骨組みが止める誤りを先に出すため. 始めた後に行を見分ける列を群を作る列にも答え直した場合なども写さない. 名前の組は ML-Quest の公開の名前を使い, このアプリに持たない). 断る文は, 群の要約の列と 1 件の行の決まった列を分けて出し, 名前を変えた表を入れ直すか ML-Pathfinder で別の列を答え直すよう添える. 断った場合は前に写した表を残す. 結果に, 写した場所, 行の数, 骨組みが読む列を添える
    - 書き出し先の決まり (置き換えてよいかの確かめ, ファイルでないものは置き換えない, 拡張子が違えば写さない, 書き出し先が登録した表そのものなら写さない, 一時ファイルに写してから置き換える, 記録とプロジェクトの確かめを写しと同じ鍵の中で行う) は並べるの反応の表と同じ (上の「13. 並べるの反応の表の分析」)
    - 書き出したファイルはデータセットではないので, データセットの一覧には並ばない
- **誤り**: 無い列, 同じ列を 2 回, 群を作るのに使えない名前の列 (ML-Quest の `GROUP_TAKEN` と同じ組. 群の要約の鍵と 1 件の行の決まった鍵の `id`, `split`), 群の数が行の数より多い, そろえた後の列の数が上限を超える, 行を見分ける列に欠けか同じ値がある場合などは, ML-EDA の理由を 422 で返して画面に出す

## 15. 課題の型への広げ方

機械学習の課題は「予測する」のほかに「作る」「並べる」「まとめる」「効果を見積もる」に分けられ, 正解の出どころ, 1 件の単位, 作り方でデータの形と確かめ方が変わる (詳しくは ML-EDA の設計の同じ節). 分析と書き出しの仕組みは ML-EDA に足し, この画面はそれを使う.
